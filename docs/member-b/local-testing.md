# Member B local testing

Run all commands from the repository root unless a step says otherwise. These
checks verify repository behavior without AWS credentials, live Cognito users,
Member C/D deployments, or an FFmpeg installation.

## Prerequisites

- Node.js 20 or a compatible newer Node release.
- Python 3.12 with `pytest`, `PyYAML`, and `Pillow==11.3.0` already installed.
- The Node dependencies declared in each Lambda `package.json` already
  installed when exercising production AWS adapters or running
  `sam build --use-container`.
- Existing frontend dependencies in `frontend/node_modules` for the production
  build.
- Docker running locally when using `sam build --use-container`; the container
  build is required because Pillow includes native Lambda dependencies.

This task does not install dependencies. Follow the group's approved setup
process when any prerequisite is missing.

## Infrastructure and backend suites

```powershell
python -m pytest infrastructure/member-b/test_template.py backend/lambdas/media-processing/tests -q
node --test backend/lambdas/upload/test/*.test.mjs backend/lambdas/storage-delete/test/*.test.mjs
```

The Python suite replaces external HTTP/S3 boundaries with behavior fakes. Its
video adapter tests inject a command runner or frame extractor, so unit tests
verify the local-only, non-interactive `fps=1` FFmpeg command, 600-second
maximum timeout, 1,024-pixel scale, JPEG quality, 900-frame/2-GiB caps, Lambda
time reserve, and cleanup behavior without invoking a local FFmpeg executable.
HTTP tests use injected dependency responses to verify HTTPS-only configuration,
the 1-MiB response cap, and invalid UTF-8 mapping without contacting Member C or
Member D. Image tests cover the 40,000,000-pixel ceiling and Pillow
decompression-bomb mapping.

To run suites separately:

```powershell
python -m pytest infrastructure/member-b/test_template.py -q
python -m pytest backend/lambdas/media-processing/tests -q
node --test backend/lambdas/upload/test/*.test.mjs
node --test backend/lambdas/storage-delete/test/*.test.mjs
```

## Frontend regression build

The repository has no `frontend/vite.config.js`. Run Vite from the frontend
working directory so it resolves the existing project configuration and
dependencies:

```powershell
Set-Location frontend
node node_modules/vite/bin/vite.js build
Set-Location ..
```

Do not commit `frontend/dist` generated by this check.

## Optional SAM checks

When AWS SAM CLI is installed:

```powershell
sam validate --template-file infrastructure/member-b/template.yaml --lint
sam build --use-container --template-file infrastructure/member-b/template.yaml
```

The structural pytest loader accepts CloudFormation intrinsic tags and is the
local fallback when SAM CLI is unavailable. A passing structural suite or SAM
build is not evidence that an AWS stack was deployed.

## Sample S3 events

The complete example events are safe, non-secret fixtures:

```text
tests/events/s3-image-upload.json
tests/events/s3-video-upload.json
```

They can be supplied to an explicitly constructed local handler test. Do not
invoke the production handler without configured dependencies: production
construction creates real AWS and HTTP adapters.

## Unit verification versus live verification

Local verification covers validation, duplicate mapping, object keys, IAM and
template structure, S3-event parsing, bounded thumbnail/video behavior,
one-frame-per-second command construction, pipeline idempotency, HTTP
serialization/timeouts, per-object deletion errors, failure handling, and
temporary-object cleanup.

Only the manual AWS workflow can verify the deployed authorizer, real browser
CORS, pre-signed PUT behavior, S3 notification delivery, Lambda layer binary,
CloudWatch execution, and live Member C/D integration. See
[`manual-aws-steps.md`](manual-aws-steps.md).
